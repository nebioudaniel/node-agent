## Conventions

- Tasks are numbered sequentially (`task-001`, `task-002`, …). Never overwrite a previous task explanation.
- If an existing task is modified later, add a new document explaining the change and link it to the previous task.
- Each document follows the 12-section format from the `with-tasks-explained` OpenCode skill: task overview, architecture/workflow, files changed, functions/methods explained, algorithms/logic, engineering decisions, Go concepts/patterns, testing, execution walkthrough, important lessons, quiz questions, future considerations.

## How to use

Read a task document when you want to understand the implementation behind a feature without re-asking. The documents are specific to the actual code in this repository — they describe real functions, real test results, and real trade-offs, not invented examples.
